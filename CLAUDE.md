# JM ProjectOP — контекст для Claude Code

Утилита для Phone Case (JUSTMOBY): бот автоматически проходит мини-игру, события записываются, из них монтируется ролик для onboard/paywall, на выходе редактируемый проект и MP4 (H.264, 30 FPS). Полное ТЗ: `docs/PRODUCT_SPEC.md`, решения: `docs/adr/`, запуск приложения: `docs/APP.md`.

## Главная идея
Проект = данные, а не видео. `render(project)` всегда детерминирован. Видео дубля это только кэш; источник истины: seed, намерения бота (intents), действия указателя (actions), события (events). Правка ассета → пересимулируются только затронутые этапы (ключи этапов, ADR 0004).

## Структура
- `packages/core` — часы (30 тиков/с), Rng, хеши, шина, **реестр расширений** (`Registry`)
- `packages/schema` — типы, пресеты и сейвзоны, валидация
- `packages/phonecase` — игра (`Game`), этапы clean/draw/stickers/reveal как `StageImpl` в реестре
- `packages/bots` — бот: стратегия → планировщик движения → «очеловечивание»
- `packages/session` — `runTake` (watchdog), `verifyTake`, `TakePlayer`, родословная дублей
- `packages/editor` — парсер текстового плана, автомонтаж по событиям
- `packages/render` — программный растеризатор (без Node-API; пригоден для браузера), QA зоны крестика
- `packages/project` — сборка проекта, ключи этапов, `rebuild`, экспорт MP4 (ffmpeg), пакетная сборка
- `packages/cli` — CLI (`npm run cli -- demo`)
- `app/` — приложение: `server.ts` (локальный API с токеном), `backend.ts` (сессия), `ui/` (HTML/JS без сборщика), `electron/` (окно)

## Команды
- `npm test` — 35 тестов движка (~1 мин, нужен ffmpeg)
- `npm run typecheck`
- `npm run build` — TS → `dist/` (нужно Electron'у: он не исполняет .ts)
- `npm run test:smoke` — компиляция + проверка собранного приложения обычным Node
- `npm run test:ui` — сквозной тест интерфейса (нужен `playwright` и Chromium)
- `npm run app` — приложение в браузере; `npm start` — в Electron
- `npm run dist:win` / `dist:mac` — установщики (в `release/`)

## Обязательные правила
1. **Детерминизм симуляции.** Только Rng из `core`, виртуальное время, никаких `Date.now`, `Math.random`. В симуляции и боте только точные IEEE-операции (`+ − × ÷ sqrt floor`); вместо `sin/cos/log` — `core/math.ts`. Бот округляет вывод до 0,01 px.
2. **Синтаксис TS только стираемый** (`erasableSyntaxOnly`): без enum, namespace, parameter properties. Типы импортировать через `import type`. Относительные импорты с расширением `.ts` (при сборке переписываются на `.js`).
3. **Отпечаток состояния** (`Game.stateHash`) описывает только совершённое состояние, не конфигурацию будущих этапов.
4. **Этап завершается, когда критерий выполнен И указатель поднят.**
5. **Новые типы этапов** регистрировать через `registry.register('stageType', …)` и объявлять зависимости в `keyParts`.
6. Render-only данные (фон, цвет чехла, quiet zone, длительности) не входят в ключи этапов.
7. Направляющие сейвзоны только в превью, никогда в экспорте.
8. Не молчать: нераспознанное, неоднозначное, невозможное в инструкции → явная ошибка; нехватка материала → `needsRetake`, а не подделка.
9. Лицензированные ассеты Phone Case в репозиторий не коммитить (см. `.gitignore`); корень ассетов настраивается.

## Состояние (что проверено, что нет)
Проверено: движок (35 тестов), интерфейс в Chromium (`test:ui`), собранный `dist/` в Node (`test:smoke`), экспорт MP4 (ffprobe).
Windows 11 (Node 22.23, Electron 33.4): `npm start` и собранный `release/win-unpacked` — окно, сборка ролика, предпросмотр и экспорт MP4 через ffmpeg из `app.asar.unpacked` (без ffmpeg в PATH); `dist:win` собирает NSIS-установщик и portable `.exe`.
**Не проверено:** сам NSIS-установщик (установка/удаление), Mac-сборка, `test:ui` на Windows.

## Известные особенности
- Размеры вывода округляются до чётных (yuv420p); на малых масштабах соотношение сторон может отличаться на пиксель.
- Порог зоны крестика (0,2) подобран на двух тестовых фонах, его надо калибровать на реальных.
- Заглушки ассетов генерирует `scripts/gen-assets.ts`.
