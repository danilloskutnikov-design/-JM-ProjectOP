# Security & access policy

This repository is planned as a **proprietary** software project.

- Recommended repository visibility: **Private**. Restrict collaborators to a necessary minimum, require 2FA where available, and review permissions periodically.
- Never commit API keys, access tokens, credentials, signing keys, .env files, unlicensed Phone Case assets, client materials, or private exports.
- Store sensitive project assets only where their usage and publication rights allow.
- Use code review and branch protections before production development.
- To report a security issue, contact the repository owner privately on GitHub or use GitHub private vulnerability reporting if enabled. Do not publish credentials or exploitation instructions in public issues.
- If a secret was committed, **revoke/rotate it immediately**. Removing it from the latest commit is not enough; Git history may still contain it.
