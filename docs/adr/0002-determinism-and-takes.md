# ADR 0002 — Детерминизм и дубли (takes)

**Статус:** принято

**Правила детерминизма**
1. Время только виртуальное: фиксированный шаг 1/30 с. Никаких `Date.now` / `performance.now` в симуляции.
2. Случайность только через `Rng` (mulberry32) и его `fork(label)`: потоки не зависят от того, сколько чисел взято у родителя.
3. В симуляции и боте только точные IEEE-операции (`+ − × ÷ sqrt floor`). `sin/cos/log/pow` заменены арифметическими версиями (`core/math.ts`).
4. Бот выдаёт значения, округлённые до 0,01 px; журнал действий хранит ровно то, что получила игра.

**Дубль (Take)** хранит три уровня: *intents* (что бот хотел), *actions* (указатель на каждый тик), *events* (семантика для монтажа). Видео — только кэш. Повтор дубля = проигрывание `actions` без бота; сверяются события и отпечаток состояния.

**Отпечаток состояния** описывает только совершённое состояние. Конфигурация более поздних этапов (нетронутый шаблон рисунка, наклейки в лотке) в него не входит, иначе замена рисунка ломала бы проверку уже валидной очистки.

**Завершение этапа:** критерий выполнен и действие закончено (указатель поднят). Жест не обрывается и не «протекает» в следующий этап.

**Родословная.** Точечный передубль продолжает состояние родителя на начале нужного этапа (`parent: {takeId, stage}`), тики абсолютные. Монтаж берёт каждый этап у дубля, чьи действия его произвели.

**Watchdog:** `STAGE_STALLED` (нет прогресса N с), `TIMEOUT`, `BOT_ERROR`; в журнал пишется `capture.failed`.
